# Class 3 – Linux Refresher and CI/CD Concepts

## 1. Introduction to CI/CD
**CI/CD** stands for **Continuous Integration** and **Continuous Deployment**.  
It is a modern software development practice that automates building, testing, and deploying applications.  
The main objective is to integrate code changes frequently and deploy them reliably with minimal manual effort.

## 2. Continuous Integration (CI)
Continuous Integration ensures that every code change is automatically validated.

### CI Workflow
- Code is pushed to a version control repository
- An automated pipeline is triggered

### Stages in CI

#### Linting
- Checks code quality and syntax
- Identifies issues early before build

#### Build
- Downloads required dependencies
- Compiles and packages the application

#### Unit Testing
- Tests individual components
- Uses mocking to simulate external dependencies

#### Security Checks
- **SCA (Software Composition Analysis)**: Detects vulnerabilities in third-party libraries
- **SAST (Static Application Security Testing)**: Analyzes source code without execution

### Artifacts in CI
Artifacts are outputs generated during the build process and reused during deployment.  
They ensure consistency between CI and CD stages.

#### Examples of Artifacts
- JAR and WAR files
- Executables (.exe)
- Gems
- Docker images

## 3. Containers and Docker

### Dockerization
Docker packages an application with its dependencies into containers.  
This guarantees consistent behavior across different environments.

### Docker Images
- Static and immutable artifacts
- Built from a base image with additional layers
- Layer caching improves build speed

### Pushing Docker Images
Docker images are pushed to an artifact repository.  
This enables versioning, sharing, and reuse across environments.

## 4. Continuous Deployment (CD)
Continuous Deployment automates application releases after CI.

### Deployment Pipeline
- Starts from stored artifacts
- Can be a separate pipeline or an extension of CI
- Reduces manual intervention and release delays

## 5. System Integration Testing (SIT)
- First environment where the complete application is deployed
- Tests interactions between system components
- Validates end-to-end functionality

## 6. IP Addressing in Deployment

### Public IP
- Assigned temporarily to instances
- Changes on stop or restart
- Not suitable for production

### Elastic IP
- Fixed and persistent IP address
- Remains unchanged across restarts
- Ideal for production environments requiring stable endpoints
